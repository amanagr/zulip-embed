Built for developers

Everything a chat integration should be.

No iframes, no WebView hacks, no vendor lock-in. Same component, same API, same look on web, iOS, Android, and desktop. Own the UX end-to-end.

One tag. Zero JS framework required.

A standard Web Component. Drop the script tag, write <zulip-chat> — done. Works in vanilla HTML, Next.js, SvelteKit, Rails, WordPress, anything that renders the DOM.

Theme every pixel via CSS variables.

Shadow DOM keeps your CSS out; --zc-* tokens let it in. Swap colors, fonts, radii, heights without forking. Light + dark presets ship built-in.

Credentials stay on-device.

Requests go browser → your Zulip server. No middle tier, no vendor data-store, no tracking. Or go read-only with a pre-baked JSON snapshot (no API key in the browser at all).

Real Zulip, not a fake.

Same REST API every Zulip client uses. Full Markdown, code blocks, KaTeX math, spoilers, reactions, message edit/delete, typing indicators, topics, channels — not a subset.

Headless when you want it.

Import ZulipClient + a transport and render your own UI. The SDK is the same on web, React Native, Flutter — you pick how much UI we ship for you.

Fast, tiny, tree-shakeable.

~55 KB gzipped for the full bundle. ESM-only, no polyfills, no jQuery, no bundled React. You ship what you use.

Every stack

One SDK, five ways to ship.

Pick the wrapper that matches your stack. Each one is a thin layer over the same Zulip client, so you only learn the API once.

<script type="module" src="https://unpkg.com/zulip-embed"></script> <zulip-chat server="https://chat.example.com" auth-token="<short-lived JWT from your backend>" channel="general" topic="welcome" theme="dark" brand-name="Acme Support" ></zulip-chat>
import {ZulipChat} from "zulip-embed-react"; export function SupportPage() { return ( <ZulipChat server="https://chat.example.com" authToken={await fetchZulipAuthToken()} channel="general" theme="dark" brandName="Acme Support" /> ); }
import { ZulipChatScreen, ZulipTransport, DARK_THEME, } from "zulip-embed-react-native"; const transport = new ZulipTransport({ serverUrl: "https://chat.example.com", authToken: process.env.ZULIP_AUTH_TOKEN!, scope: { channel: "general" }, }); export default function SupportScreen() { return ( <ZulipChatScreen transport={transport} scope={{ channel: "general" }} theme={DARK_THEME} brandName="Acme Support" /> ); }
// flutter pub add zulip_embed import 'package:zulip_embed/zulip_embed.dart'; ZulipChat( transport: ZulipTransport( serverUrl: Uri.parse('https://chat.example.com'), email: 'you@example.com', apiKey: '...', ), channel: 'general', topic: 'welcome', theme: ZulipTheme.dark, )
import {ZulipClient, ZulipTransport} from "zulip-embed"; const transport = new ZulipTransport({ serverUrl: "https://chat.example.com", authToken: await fetchZulipAuthToken(), scope: { channel: "general" }, }); const client = new ZulipClient({ transport, scope: { channel: "general" }, }); client.subscribe(() => render(client.getState().messages)); await client.connect();

Shipped patterns

What people build with it.

Not just a chat window. Use the primitives to assemble the integration your product actually needs.

💬

Intercom-style support messenger

Floating bottom-right launcher that expands into a full thread. Pass mode="floating" and you're done — the chat bubble, open state, and scrolling are handled.

🏛️

Community hub

Embed a public channel as a read-only snapshot on your marketing site. No API key in the browser; refresh the JSON on a cron. Works with static hosts.

💡

Product feedback thread

Drop the widget on each feature docs page, with channel="feedback" and topic set to the feature name. Threads grouped automatically via Zulip topics.

🛠️

Admin inbox clone

Compose <zulip-channel-list>, <zulip-topic-list>, and <zulip-chat> into a three-pane layout. You own routing.

📱

Native mobile chat screen

Same Zulip backend, real React Native FlatList + TextInput. Ship chat inside your existing Expo / bare RN app without a WebView.

🧪

Internal tools

Add a chat sidebar to your admin panel so support and engineering can collaborate inline. On-premise Zulip keeps it inside your network.

Honest comparison

Why not the usual chat SaaS?

If you want a hosted widget with a monthly seat price, there are great options. If you want to own the backend and the UI, without per-seat pricing, this is for you.

Zulip Embed Hosted chat SaaS
License Apache-2.0 · self-host anywhere Proprietary · vendor-hosted
Pricing Free forever (you host Zulip) Per-seat or per-MAU
Data residency Your server, your rules Vendor-controlled
UI customization CSS custom properties + full source Theming panel, fixed layout
Framework support Web / React / RN / Flutter Usually web + RN only
Threaded conversations Native Zulip topics Flat or bolt-on
Leaves your page? Never (direct to your Zulip) Always (vendor cloud)
